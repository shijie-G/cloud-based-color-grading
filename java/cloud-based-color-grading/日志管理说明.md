# 日志管理说明

## 日志追加模式说明

### 追加模式（Append Mode）

所有日志文件都配置为**追加模式**（`<append>true</append>`），这意味着：

**同一天内重启服务：**
- ✅ 日志会追加到当前日志文件末尾
- ✅ 不会覆盖或删除已有日志
- ✅ 保持日志的连续性

**示例：**
```
# 第一次启动（2026-01-13 09:00）
logs/auth-service/auth-service.log
2026-01-13 09:00:00.123 [main] INFO  - Application started

# 重启服务（2026-01-13 10:00）
logs/auth-service/auth-service.log
2026-01-13 09:00:00.123 [main] INFO  - Application started
2026-01-13 10:00:00.456 [main] INFO  - Application started  ← 追加到文件末尾

# 再次重启（2026-01-13 11:00）
logs/auth-service/auth-service.log
2026-01-13 09:00:00.123 [main] INFO  - Application started
2026-01-13 10:00:00.456 [main] INFO  - Application started
2026-01-13 11:00:00.789 [main] INFO  - Application started  ← 继续追加
```

**跨天滚动：**
- 午夜（00:00:00）时，当前日志文件会被移动到归档目录
- 创建新的当前日志文件
- 新的一天从空文件开始

**示例：**
```
# 2026-01-13 23:59:59
logs/auth-service/auth-service.log  （包含当天所有日志）

# 2026-01-14 00:00:00（午夜滚动）
logs/auth-service/auth-service.log  （新文件，空的）
logs/auth-service/2026/2026-01/2026-01-13/auth-service.log  （昨天的日志已归档）

# 2026-01-14 09:00:00（重启服务）
logs/auth-service/auth-service.log  （追加到今天的日志文件）
```

## 日志存放位置

所有微服务的日志文件按模块分类存放在项目根目录的 `logs/` 文件夹中，每个模块有独立的文件夹，并按年份/月份/日期进行分类归档。

### 日志目录结构

```
logs/
├── auth-service/                    # Auth Service 日志目录
│   ├── auth-service.log            # 当前服务日志
│   ├── security-audit.log          # 当前安全审计日志
│   └── 2026/                       # 按年份归档
│       └── 2026-01/                # 按月份归档
│           ├── 2026-01-12/         # 按日期归档
│           │   ├── auth-service.log
│           │   └── security-audit.log
│           └── 2026-01-13/
│               ├── auth-service.log
│               └── security-audit.log
│
├── authz-service/                   # Authz Service 日志目录
│   ├── authz-service.log           # 当前服务日志
│   ├── security-audit.log          # 当前安全审计日志
│   └── 2026/                       # 按年份归档
│       └── 2026-01/                # 按月份归档
│           └── 2026-01-12/         # 按日期归档
│               ├── authz-service.log
│               └── security-audit.log
│
└── gateway/                         # Gateway 日志目录
    ├── gateway.log                 # 当前服务日志
    ├── security-audit.log          # 当前安全审计日志
    └── 2026/                       # 按年份归档
        └── 2026-01/                # 按月份归档
            └── 2026-01-12/         # 按日期归档
                ├── gateway.log
                └── security-audit.log
```

## 日志类型说明

### 1. 服务日志（General Logs）

**文件：**
- `logs/auth-service/auth-service.log` - Auth Service 当前服务日志
- `logs/authz-service/authz-service.log` - Authz Service 当前服务日志
- `logs/gateway/gateway.log` - Gateway 当前服务日志

**归档路径：**
- `logs/auth-service/2026/2026-01/2026-01-12/auth-service.log`
- `logs/authz-service/2026/2026-01/2026-01-12/authz-service.log`
- `logs/gateway/2026/2026-01/2026-01-12/gateway.log`

**内容：**
- 应用启动和关闭信息
- 业务操作日志
- 数据库操作日志
- Redis操作日志
- HTTP请求和响应日志
- 异常和错误信息

**日志级别：** INFO、WARN、ERROR

**保留时间：** 30天

**示例：**
```
2026-01-12 23:00:00.123 [main] INFO  c.g.authservice.AuthServiceApplication - Starting AuthServiceApplication
2026-01-12 23:00:01.456 [http-nio-8081-exec-1] INFO  c.g.authservice.controller.AuthController - User login attempt: admin
2026-01-12 23:00:01.789 [http-nio-8081-exec-1] INFO  c.g.authservice.service.impl.AuthServiceImpl - Login successful for user: admin
```

---

### 2. 安全审计日志（Security Audit Logs）

**文件：**
- `logs/auth-service/security-audit.log` - Auth Service 当前安全审计日志
- `logs/authz-service/security-audit.log` - Authz Service 当前安全审计日志
- `logs/gateway/security-audit.log` - Gateway 当前安全审计日志

**归档路径：**
- `logs/auth-service/2026/2026-01/2026-01-12/security-audit.log`
- `logs/authz-service/2026/2026-01/2026-01-12/security-audit.log`
- `logs/gateway/2026/2026-01/2026-01-12/security-audit.log`

**内容：**
- 用户登录成功/失败
- 用户登出
- 令牌刷新
- 账户锁定/解锁
- 用户创建/更新/禁用
- 密码重置
- 权限检查
- 敏感操作记录

**日志级别：** INFO、WARN、ERROR

**保留时间：** 90天（安全审计需要更长的保留期）

**示例：**
```
2026-01-12 23:00:01.789 [http-nio-8081-exec-1] INFO  c.g.authservice.security.SecurityAuditLogger - [LOGIN_SUCCESS] User: admin, IP: 192.168.1.100
2026-01-12 23:00:02.123 [http-nio-8081-exec-2] WARN  c.g.authservice.security.SecurityAuditLogger - [LOGIN_FAILURE] User: hacker, IP: 192.168.1.200, Reason: Invalid password
2026-01-12 23:00:03.456 [http-nio-8081-exec-3] WARN  c.g.authservice.security.SecurityAuditLogger - [ACCOUNT_LOCKED] User: testuser, IP: 192.168.1.150, Reason: Too many failed attempts
```

## 日志格式

所有日志使用统一的格式：

```
%d{yyyy-MM-dd HH:mm:ss.SSS} [%thread] %-5level %logger{36} - %msg%n
```

**格式说明：**

| 占位符 | 说明 | 示例 |
|--------|------|------|
| %d{yyyy-MM-dd HH:mm:ss.SSS} | 日期时间（精确到毫秒） | 2026-01-12 23:00:00.123 |
| [%thread] | 线程名称 | [http-nio-8081-exec-1] |
| %-5level | 日志级别（左对齐，5个字符宽度） | INFO  |
| %logger{36} | Logger名称（最多36个字符） | c.g.authservice.controller.AuthController |
| %msg | 日志消息 | User login attempt: admin |
| %n | 换行符 | - |

**完整示例：**
```
2026-01-12 23:00:00.123 [http-nio-8081-exec-1] INFO  c.g.authservice.controller.AuthController - User login attempt: admin
```

## 日志滚动策略

### 按日期分层归档

所有日志文件都采用按日期分层归档的策略：

**归档规则：**
- 每天午夜（00:00:00）自动创建新的日志文件
- 旧日志文件自动归档到 `年份/月份/日期/` 目录结构中
- 当前日志始终保存在模块根目录的 `服务名.log` 文件中

**归档路径格式：**
```
logs/{模块名}/{年份}/{年份-月份}/{年份-月份-日期}/{日志文件名}
```

**示例：**
```
# 2026-01-12 当天
logs/auth-service/auth-service.log              # 当前日志

# 2026-01-13 午夜后
logs/auth-service/auth-service.log              # 新的当前日志
logs/auth-service/2026/2026-01/2026-01-12/auth-service.log   # 昨天的日志（自动归档）

# 2026-02-01 午夜后
logs/auth-service/auth-service.log              # 当前日志
logs/auth-service/2026/2026-01/2026-01-31/auth-service.log   # 1月31日的日志
logs/auth-service/2026/2026-02/2026-02-01/auth-service.log   # 2月1日的日志（新月份）

# 2027-01-01 午夜后
logs/auth-service/auth-service.log              # 当前日志
logs/auth-service/2026/2026-12/2026-12-31/auth-service.log   # 2026年最后一天
logs/auth-service/2027/2027-01/2027-01-01/auth-service.log   # 2027年第一天（新年份）
```

### 自动清理

**服务日志：** 保留30天，超过30天的日志文件自动删除

**安全审计日志：** 保留90天，超过90天的日志文件自动删除

**清理机制：**
- Logback会自动计算日志文件的年龄
- 超过保留期限的整个日期文件夹会被自动删除
- 空的月份和年份文件夹也会被自动清理

## 查看日志

### 1. 查看当前日志

```bash
# 查看Auth Service当前日志
tail -f logs/auth-service/auth-service.log

# 查看Authz Service当前日志
tail -f logs/authz-service/authz-service.log

# 查看Gateway当前日志
tail -f logs/gateway/gateway.log

# 查看Auth Service安全审计日志
tail -f logs/auth-service/security-audit.log
```

### 2. 查看历史日志

```bash
# 查看指定日期的Auth Service日志
cat logs/auth-service/2026/2026-01/2026-01-12/auth-service.log

# 查看指定月份的所有日志
cat logs/auth-service/2026/2026-01/*/auth-service.log

# 查看指定年份的所有日志
cat logs/auth-service/2026/*/*/auth-service.log

# 查看最近100行
tail -n 100 logs/auth-service/auth-service.log

# 查看最早100行
head -n 100 logs/auth-service/auth-service.log
```

### 3. 搜索日志

```bash
# 在当前日志中搜索包含"ERROR"的日志
grep "ERROR" logs/auth-service/auth-service.log

# 在指定日期的日志中搜索
grep "ERROR" logs/auth-service/2026/2026-01/2026-01-12/auth-service.log

# 在整个月份的日志中搜索
grep "ERROR" logs/auth-service/2026/2026-01/*/auth-service.log

# 在所有历史日志中搜索
grep -r "ERROR" logs/auth-service/2026/

# 搜索特定用户的登录日志
grep "User: admin" logs/auth-service/security-audit.log

# 搜索特定时间段的日志
grep "2026-01-12 23:" logs/auth-service/auth-service.log

# 搜索并显示上下文（前后各3行）
grep -C 3 "Exception" logs/auth-service/auth-service.log
```

### 4. 统计日志

```bash
# 统计当前日志中ERROR的数量
grep -c "ERROR" logs/auth-service/auth-service.log

# 统计指定日期ERROR的数量
grep -c "ERROR" logs/auth-service/2026/2026-01/2026-01-12/auth-service.log

# 统计整个月份ERROR的数量
grep -r "ERROR" logs/auth-service/2026/2026-01/ | wc -l

# 统计登录失败次数
grep -c "LOGIN_FAILURE" logs/auth-service/security-audit.log

# 统计各日志级别的数量
grep -o "INFO\|WARN\|ERROR" logs/auth-service/auth-service.log | sort | uniq -c
```

### 5. 按日期查看日志

```bash
# 列出所有日期的日志
ls -la logs/auth-service/2026/2026-01/

# 查看最近7天的日志
find logs/auth-service/2026/2026-01/ -name "auth-service.log" -mtime -7

# 查看指定日期范围的日志（2026-01-10 到 2026-01-15）
for date in {10..15}; do
  echo "=== 2026-01-$date ==="
  cat logs/auth-service/2026/2026-01/2026-01-$date/auth-service.log 2>/dev/null || echo "No logs"
done
```

## 日志级别

### 级别说明

| 级别 | 说明 | 使用场景 |
|------|------|----------|
| ERROR | 错误 | 系统异常、业务错误、需要立即处理的问题 |
| WARN | 警告 | 潜在问题、不影响系统运行但需要关注 |
| INFO | 信息 | 重要的业务操作、系统状态变化 |
| DEBUG | 调试 | 详细的调试信息（生产环境不启用） |
| TRACE | 跟踪 | 最详细的跟踪信息（生产环境不启用） |

### 当前配置

**生产环境：** INFO级别（只记录INFO、WARN、ERROR）

**开发环境：** 可以修改为DEBUG级别以获取更详细的日志

## 修改日志配置

### 修改日志级别

编辑对应服务的 `logback-spring.xml` 文件：

**文件位置：**
- `auth-service/src/main/resources/logback-spring.xml`
- `authz-service/src/main/resources/logback-spring.xml`
- `gateway/src/main/resources/logback-spring.xml`

**修改Root Logger级别：**
```xml
<!-- 修改前：INFO级别 -->
<root level="INFO">
    <appender-ref ref="CONSOLE"/>
    <appender-ref ref="FILE"/>
</root>

<!-- 修改后：DEBUG级别 -->
<root level="DEBUG">
    <appender-ref ref="CONSOLE"/>
    <appender-ref ref="FILE"/>
</root>
```

**修改特定包的日志级别：**
```xml
<!-- 只调整MyBatis的日志级别为DEBUG -->
<logger name="cn.gsjgsj.authservice.mapper" level="DEBUG"/>
```

### 修改日志保留时间

```xml
<!-- 修改前：保留30天 -->
<rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
    <fileNamePattern>logs/auth-service/%d{yyyy,aux}/%d{yyyy-MM,aux}/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>
    <maxHistory>30</maxHistory>
</rollingPolicy>

<!-- 修改后：保留60天 -->
<rollingPolicy class="ch.qos.logback.core.rolling.TimeBasedRollingPolicy">
    <fileNamePattern>logs/auth-service/%d{yyyy,aux}/%d{yyyy-MM,aux}/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>
    <maxHistory>60</maxHistory>
</rollingPolicy>
```

**说明：** `%d{format,aux}` 中的 `aux` 表示辅助时间戳，用于支持多级日期目录结构。

### 修改日志归档路径格式

```xml
<!-- 当前格式：年份/月份/日期（使用aux辅助时间戳） -->
<fileNamePattern>logs/auth-service/%d{yyyy,aux}/%d{yyyy-MM,aux}/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>

<!-- 修改为：只按日期（不分层） -->
<fileNamePattern>logs/auth-service/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>

<!-- 修改为：按年份/日期（不分月份） -->
<fileNamePattern>logs/auth-service/%d{yyyy,aux}/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>
```

**说明：** 
- `%d{yyyy,aux}` - 年份目录（aux表示辅助时间戳）
- `%d{yyyy-MM,aux}` - 月份目录（aux表示辅助时间戳）
- `%d{yyyy-MM-dd}` - 日期目录（主时间戳，用于触发滚动）
- 最后一个 `%d{}` 不能使用 `aux`，它是主时间戳，决定何时滚动日志

### 修改日志文件位置

```xml
<!-- 修改前：存放在项目根目录的logs文件夹 -->
<file>logs/auth-service/auth-service.log</file>

<!-- 修改后：存放在指定的绝对路径 -->
<file>/var/log/auth-service/auth-service.log</file>
<fileNamePattern>/var/log/auth-service/%d{yyyy}/%d{yyyy-MM}/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>
```

**注意：** 修改配置后需要重启服务才能生效。

```bash
# 监控Auth Service所有ERROR日志
tail -f logs/auth-service/auth-service.log | grep "ERROR"

# 监控所有服务的ERROR日志

tail -f logs/auth-service/security-audit.log
```

建议每天检查以下内容：

```bash
# 检查今天的ERROR日志
grep "ERROR" logs/auth-service/auth-service.log | tail -n 50

# 检查昨天的ERROR日志
grep "ERROR" logs/auth-service/2026/2026-01/2026-01-12/auth-service.log

grep "ACCOUNT_LOCKED" logs/auth-service/security-audit.log
```

**推荐工具：**
- **ELK Stack**（Elasticsearch + Logstash + Kibana）：企业级日志分析平台
- **Grafana Loki**：轻量级日志聚合系统


## 常见问题

### Q1: 日志文件太大怎么办？

A: 日志文件会自动按日期滚动并分层归档。如果单个日志文件仍然很大，可以：
1. 调整日志级别（从DEBUG改为INFO）
2. 减少日志保留天数
3. 定期备份并清理旧日志

### Q2: 如何查找特定时间段的日志？

A: 使用日期路径直接访问：
```bash
# 查找2026年1月12日的日志
cat logs/auth-service/2026/2026-01/2026-01-12/auth-service.log

# 查找2026年1月的所有日志
cat logs/auth-service/2026/2026-01/*/auth-service.log
```

### Q3: 日志文件被删除了怎么办？

A: 日志文件会在服务启动时自动创建。如果误删除，重启服务即可重新生成。

### Q4: 如何清理旧日志？

A: Logback会自动清理超过保留期限的日志。如需手动清理：
```bash
# 删除2025年的所有日志
rm -rf logs/auth-service/2025/
rm -rf logs/authz-service/2025/
rm -rf logs/gateway/2025/

# 删除指定月份的日志
rm -rf logs/auth-service/2026/2026-01/
```

### Q5: 生产环境日志配置建议？

A: 生产环境建议：
- 日志级别：INFO
- 服务日志保留：30-60天
- 安全审计日志保留：90-180天
- 使用日志聚合工具（如ELK）
- 定期备份重要日志（按月或按年）
- 设置日志告警（ERROR日志超过阈值时告警）
- 使用分层归档便于管理和查找

## 技术说明：Logback多级日期目录配置

### %d{format,aux} 语法说明

在Logback的 `TimeBasedRollingPolicy` 中，要实现多级日期目录结构（如 `2026/2026-01/2026-01-12/`），需要使用 `aux` 辅助时间戳参数。

**语法格式：**
```xml
<fileNamePattern>logs/auth-service/%d{yyyy,aux}/%d{yyyy-MM,aux}/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>
```

**参数说明：**

| 参数 | 说明 | 示例 |
|------|------|------|
| `%d{yyyy,aux}` | 辅助时间戳 - 年份目录 | `2026/` |
| `%d{yyyy-MM,aux}` | 辅助时间戳 - 月份目录 | `2026-01/` |
| `%d{yyyy-MM-dd}` | 主时间戳 - 日期目录（触发滚动） | `2026-01-12/` |

**重要规则：**

1. **主时间戳（Primary）**：最后一个 `%d{}` 必须不带 `aux` 参数，它决定日志滚动的时机
2. **辅助时间戳（Auxiliary）**：前面的 `%d{}` 必须带 `aux` 参数，用于创建多级目录
3. **时间格式递进**：从粗粒度到细粒度（年 → 月 → 日）
4. **滚动触发**：根据主时间戳的格式决定滚动周期（`yyyy-MM-dd` = 每天滚动）

**错误示例（不支持）：**
```xml
<!-- ❌ 错误：多个%d{}都不带aux -->
<fileNamePattern>logs/auth-service/%d{yyyy}/%d{yyyy-MM}/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>

<!-- ❌ 错误：主时间戳带了aux -->
<fileNamePattern>logs/auth-service/%d{yyyy,aux}/%d{yyyy-MM,aux}/%d{yyyy-MM-dd,aux}/auth-service.log</fileNamePattern>

<!-- ❌ 错误：在%d{}内部使用路径分隔符 -->
<fileNamePattern>logs/auth-service/%d{yyyy/yyyy-MM/yyyy-MM-dd}/auth-service.log</fileNamePattern>
```

**正确示例：**
```xml
<!-- ✅ 正确：三级目录（年/月/日） -->
<fileNamePattern>logs/auth-service/%d{yyyy,aux}/%d{yyyy-MM,aux}/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>

<!-- ✅ 正确：两级目录（年/日） -->
<fileNamePattern>logs/auth-service/%d{yyyy,aux}/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>

<!-- ✅ 正确：单级目录（日） -->
<fileNamePattern>logs/auth-service/%d{yyyy-MM-dd}/auth-service.log</fileNamePattern>
```

**工作原理：**

1. **每天午夜（00:00:00）**，Logback检查主时间戳（`%d{yyyy-MM-dd}`）
2. 如果日期变化，触发日志滚动
3. 根据新日期计算所有时间戳（包括辅助时间戳）
4. 创建完整的目录结构：`2026/2026-01/2026-01-13/`
5. 将旧日志文件移动到归档路径
6. 创建新的当前日志文件

**目录创建示例：**

```
# 2026-01-12 运行中
logs/auth-service/auth-service.log              # 当前日志

# 2026-01-13 00:00:00 触发滚动
1. 检测到日期变化（2026-01-12 → 2026-01-13）
2. 计算归档路径：
   - %d{yyyy,aux} = 2026
   - %d{yyyy-MM,aux} = 2026-01
   - %d{yyyy-MM-dd} = 2026-01-12
3. 创建目录：logs/auth-service/2026/2026-01/2026-01-12/
4. 移动文件：auth-service.log → 2026/2026-01/2026-01-12/auth-service.log
5. 创建新文件：auth-service.log（空文件）

# 结果
logs/auth-service/
├── auth-service.log                             # 新的当前日志
└── 2026/
    └── 2026-01/
        └── 2026-01-12/
            └── auth-service.log                 # 归档的昨天日志
```

**性能考虑：**

- ✅ 辅助时间戳不影响性能，只在滚动时计算一次
- ✅ 目录结构便于文件系统索引和查找
- ✅ 按月份分组便于备份和清理
- ✅ 自动创建目录，无需手动维护

**参考文档：**
- Logback官方文档：https://logback.qos.ch/manual/appenders.html#TimeBasedRollingPolicy
- 多级目录配置：https://logback.qos.ch/manual/appenders.html#multiple-%25d
