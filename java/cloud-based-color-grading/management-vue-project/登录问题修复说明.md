# 登录问题修复说明

## 问题描述
前端登录页面没有真正调用后端API进行验证，使用的是模拟数据，导致任何账号密码都能登录。

## 问题原因
`src/stores/user.ts` 中的 `login()` 函数使用了硬编码的模拟数据，没有调用真实的后端API。

## 修复内容

### 1. 创建认证API接口 (`src/api/auth.ts`)
- `login()` - 用户登录
- `logout()` - 用户登出
- `refreshToken()` - 刷新Token

### 2. 创建用户API接口 (`src/api/user.ts`)
- `getUserInfo()` - 获取当前用户信息
- `getUsers()` - 获取用户列表
- `getUserById()` - 根据ID获取用户
- `createUser()` - 创建用户
- `updateUser()` - 更新用户
- `deleteUser()` - 删除用户

### 3. 修复用户Store (`src/stores/user.ts`)
- 导入真实的API函数
- `login()` 函数现在调用 `loginApi()` 进行真实验证
- `logout()` 函数调用 `logoutApi()` 通知后端
- `getUserInfo()` 函数调用 `getUserInfoApi()` 获取用户信息
- 添加错误处理，登录失败时清理状态

### 4. 更新API统一导出 (`src/api/index.ts`)
- 导出认证相关API
- 导出用户相关API

## 常见问题排查

### 问题1: 请求404 Not Found
**原因**: Gateway未启动或路由配置错误
**解决**: 
- 检查Gateway是否在8080端口运行
- 检查 `gateway/src/main/resources/application.yml` 中的路由配置

### 问题2: 请求超时
**原因**: Auth Service未启动
**解决**: 启动 auth-service (端口8081)

### 问题3: CORS跨域错误
**原因**: Gateway的CORS配置问题
**解决**: 检查 `application.yml` 中的 `globalcors` 配置

### 问题4: Redis连接失败
**原因**: Redis服务未启动或连接配置错误
**解决**: 
- 检查Redis是否运行
- 检查 `application.yml` 中的Redis配置

### 问题5: Token验证失败
**原因**: JWT密钥不一致
**解决**: 确保Gateway和Auth Service使用相同的JWT密钥

## 后端API端点

根据文档，后端API结构如下：

```
Gateway (8080)
  ├─ /auth/login          -> Auth Service (8081)
  ├─ /auth/logout         -> Auth Service (8081)
  ├─ /auth/refresh        -> Auth Service (8081)
  ├─ /users/**            -> Auth Service (8081)
  ├─ /roles/**            -> Authz Service (8082)
  ├─ /permissions/**      -> Authz Service (8082)
  └─ /menus/**            -> Authz Service (8082)
```

## 登录流程

```
1. 用户输入账号密码
   ↓
2. 前端调用 userStore.login()
   ↓
3. 发送 POST /auth/login 到 Gateway (8080)
   ↓
4. Gateway转发到 Auth Service (8081)
   ↓
5. Auth Service验证:
   - 检查账户是否锁定 (Redis)
   - 查询用户信息 (MySQL)
   - BCrypt验证密码
   - 生成JWT Token
   - 存储Token到Redis
   ↓
6. 返回登录响应 (token, userId, roles, permissions)
   ↓
7. 前端保存Token到localStorage
   ↓
8. 跳转到首页
```
