# WorkstationPage 布局高度分析文档

## 📐 整体布局结构

```
editor-container (100vh)
├── TopNavbar (5vh, flex-shrink: 0)
└── main-content (flex: 1, height: 95vh) ⚠️ 问题所在！
    ├── ImageDisplay (100% of parent)
    │   ├── ImagePreview (calc(100% - galleryHeight vh - 0.5vh))
    │   ├── GalleryResizer (0.5vh, flex-shrink: 0)
    │   └── ImageGallery (galleryHeight vh)
    ├── PanelResizer
    └── AdjustPanel
```

## 🔍 问题分析

### 问题1: main-content 的冲突设置

在 `WorkstationPage.vue` 中：

```css
.main-content {
  display: flex;
  flex: 1;           /* 自动填充剩余空间 */
  height: 95vh;      /* 固定高度 ⚠️ 冲突！*/
  overflow: hidden;
}
```

**冲突说明：**
- `flex: 1` 表示占据父容器的剩余空间
- `height: 95vh` 表示固定高度为95vh
- 当两者同时存在时，`height: 95vh` 会覆盖 `flex: 1` 的效果

**实际计算：**
```
editor-container = 100vh
TopNavbar = 5vh (flex-shrink: 0)
main-content 应该 = 100vh - 5vh = 95vh (通过 flex: 1)
但是 main-content 又设置了 height: 95vh

结果：main-content 实际高度 = 95vh
总高度 = 5vh + 95vh = 100vh ✅
```

看起来没问题，但是...

### 问题2: 浏览器渲染的微小差异

**可能的原因：**

1. **边框/边距累积**
   - 各个组件可能有隐藏的 border 或 margin
   - 即使设置了 `box-sizing: border-box`，某些情况下仍可能有1px的差异

2. **flex布局的舍入误差**
   - 浏览器在计算flex布局时可能产生亚像素舍入
   - 95vh 转换为像素时可能有小数，导致舍入误差

3. **vh单位的精度问题**
   - vh 是基于视口高度的百分比
   - 当视口高度不是整数倍时，vh 计算可能有微小误差

## 🔧 解决方案

### 方案1: 移除冗余的 height 设置（推荐）

```css
.main-content {
  display: flex;
  flex: 1;           /* 只用 flex，让它自动计算 */
  /* height: 95vh; */ /* 删除这行 */
  overflow: hidden;
}
```

**优点：**
- 让 flex 布局自动计算高度
- 避免固定高度和 flex 的冲突
- 更灵活，适应不同屏幕

### 方案2: 使用 calc() 精确计算

```css
.main-content {
  display: flex;
  height: calc(100vh - 5vh);  /* 精确计算 */
  overflow: hidden;
}
```

### 方案3: 使用 100% 而不是 vh

```css
.editor-container {
  display: flex;
  flex-direction: column;
  width: 100%;
  height: 100%;  /* 改为 100% */
  overflow: hidden;
}

.main-content {
  display: flex;
  flex: 1;
  overflow: hidden;
}
```

## 📊 当前高度计算详情

### galleryHeight = 25vh 时

**ImageDisplay 内部：**
```
ImagePreview = calc(100% - 25vh - 0.5vh)
             = calc(95vh - 25vh - 0.5vh)  (因为父容器是95vh)
             = 69.5vh

GalleryResizer = 0.5vh

ImageGallery = 25vh

总计 = 69.5vh + 0.5vh + 25vh = 95vh ✅
```

### 拖动时的计算（GalleryResizer.vue）

```typescript
const newHeightPx = leftPanelRect.bottom - e.clientY
const newHeightVh = (newHeightPx / window.innerHeight) * 100
```

**问题：**
- 拖动时基于 `window.innerHeight` 计算
- 但 ImageDisplay 的实际高度是 95vh，不是 100vh
- 这可能导致微小的计算差异

## 🐛 可能的其他问题

### 1. GalleryResizer 的高度

```css
.gallery-resizer {
  height: 0.5vh;  /* 可能在某些分辨率下舍入为1px */
}
```

**建议：** 改为固定像素值
```css
.gallery-resizer {
  height: 4px;  /* 固定像素，避免vh舍入误差 */
}
```

### 2. ImageGallery 的 header 高度

```css
.gallery-header {
  padding: 0.8vh 1.5vw;  /* vh单位可能有舍入误差 */
}
```

**建议：** 改为固定像素值
```css
.gallery-header {
  padding: 8px 1.5vw;  /* 垂直方向用px */
}
```

## 📝 总结

**主要问题：**
1. `main-content` 同时设置了 `flex: 1` 和 `height: 95vh`，造成冗余
2. vh 单位在不同分辨率下可能有亚像素舍入误差
3. 多个组件使用 vh 单位累积可能产生1-2px的误差

**推荐解决方案：**
1. 移除 `main-content` 的 `height: 95vh`，只保留 `flex: 1`
2. 将小尺寸元素（如 GalleryResizer）改为固定像素值
3. 垂直方向的 padding 使用 px 而不是 vh

**预期效果：**
- 消除高度差异
- 布局更稳定
- 适应不同分辨率
