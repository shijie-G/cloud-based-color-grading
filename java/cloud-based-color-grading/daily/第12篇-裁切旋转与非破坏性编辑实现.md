# 周记第十二篇：裁切旋转与非破坏性编辑实现

本周主要研究裁切、旋转、翻转以及非破坏性编辑机制。裁切功能在修图软件中非常常见，但如果直接覆盖原图，会导致用户无法恢复。因此本系统采用非破坏性编辑思路：原图 src 始终保留，裁切后的 editedSrc 和裁切状态 cropStateJson 单独保存。当用户需要恢复时，可以清除裁切数据并重新显示原图。imageDB 中提供 updateCropData、getCropData、clearCropData 等方法，ImageRepository 也提供 clearCrop 操作，保证裁切数据管理统一。

前端裁切功能由 CropTool、CropPanel 和 WorkstationPage 中的相关事件共同完成。用户进入裁切面板后，可以选择固定比例或自由比例，拖动裁切框确定区域，也可以执行旋转和水平、垂直翻转。系统会在用户确认后通过 Canvas 按裁切框重新绘制图片，生成新的 editedSrc，同时保存裁切矩形、旋转角度、翻转状态等信息。取消操作时则恢复原有预览，避免误操作。

非破坏性编辑还体现在调色、滤镜和历史记录中。基础调色参数保存为 adjustmentsJson，滤镜配置保存为 filterConfigJson，个性化图层保存为 personalizeLayersJson，撤销重做历史保存到 history 表。展示图片时，系统根据原图、裁切结果和各类参数动态生成 processedSrc，而不是永久改变原始图片。本周通过分析这一机制，我理解到专业修图系统必须重视可恢复性和可追溯性。非破坏性编辑虽然会增加数据结构和状态管理复杂度，但可以显著提升用户体验和系统可靠性。
