# 周记第四篇：系统数据分析

本周主要分析系统中涉及的数据对象、数据流向和存储方式。系统既包含后端用户权限数据，也包含前端图片编辑数据。后端数据以关系型数据库为主，核心表包括用户表、角色表、权限表、菜单表、用户角色关联表、角色权限关联表和菜单权限关联表。这些表共同构成 RBAC 权限模型，其中用户通过角色获得权限，权限再对应具体资源路径和 HTTP 方法，菜单用于前端功能入口组织。该设计可以支持管理员维护角色、权限和菜单，也方便网关在请求进入后进行权限判断。

前端图片数据主要保存在 IndexedDB 中。工作台使用 WorkstationDB 数据库，其中 images 表保存图片原图、缩略图、文件哈希、上传时间、最后修改时间、相册编号、收藏状态、删除状态、标签、排序值等信息；同时还保存 editedSrc、adjustmentsJson、cropStateJson、filterConfigJson、personalizeLayersJson 等编辑字段。albums 表保存相册编号、相册名称、创建时间、排序和封面图片；history 表保存撤销重做历史包。这样的设计体现了非破坏性编辑思想：原图不被覆盖，调色参数、裁切状态、滤镜配置和个性化图层都以独立字段保存，需要展示时再重新合成。

本周还梳理了典型数据流程。用户上传图片时，前端先计算文件哈希避免重复上传，再读取 DataURL，生成缩略图，最后保存到 IndexedDB。用户调色时，界面参数变化触发处理链，基础调色、HSL、蒙版和滤镜通过 Worker 处理后生成预览图，同时参数被记录到历史栈并持久化。用户切换图片时，系统从 IndexedDB 恢复图片、调色参数、裁切状态、滤镜配置和历史记录。后端登录流程中，用户密码使用 BCrypt 校验，登录成功后生成 JWT 并写入 Redis，后续请求由 Gateway 验证 Token 与权限。通过本周数据分析，我对数据库设计和前后端数据交互有了完整认识。
