# 周记第八篇：工作台图片上传与本地存储实现

本周主要研究工作台中的图片上传和本地存储功能。图片上传是调色流程的起点，系统需要在用户选择图片后完成读取、去重、缩略图生成、数据库保存和界面更新。代码中 imageUploadHelper.ts 提供了统一上传逻辑，首先根据文件名、文件大小和 MIME 类型生成 fileHash，然后调用 imageDB.existsByHash 判断是否已经存在，避免重复添加同一图片。若图片未重复，则使用 FileReader 将文件读取为 DataURL，方便 Canvas 和 img 标签直接显示。

上传过程中还会生成缩略图。系统创建 Image 对象加载原图，再使用 Canvas 按比例压缩到最大 1280 像素，并以 JPEG 格式保存为缩略图。这样既能保证图库列表展示清晰，又能避免直接展示大图造成内存和渲染压力。随后系统构建 ImageDBItem 数据对象，包含 id、name、blob、src、thumbnail、uploadTime、lastModified、fileHash、albumId、isFavorite、isDeleted、tags、sortOrder 等字段，并通过 ImageRepository 保存到 IndexedDB。

工作台中的 useImageState 组合式函数负责维护 imageSrc、uploadedImages、selectedImageId 和 isLoadingFromDB 等状态。上传完成后，图片会加入已上传列表，并设置为当前选中图片。选择图片时，系统更新预览源，并与调色处理链联动。IndexedDB 的 imageDB 类提供 saveImage、getAllImages、getImage、deleteImage、clearAll 等方法，支持页面刷新后恢复图片列表。本周实现和分析后，我理解到图片上传模块虽然表面简单，但它连接了用户交互、本地数据库、调色工作台和图库模块，是整个系统数据流的基础。
