# 周记第五篇：总体体系结构设计和数据库设计

本周主要完成总体体系结构设计和数据库设计。系统采用前后端分离架构，前端是基于 Vue 3 + TypeScript 的单页应用，后端是基于 Spring Boot 的微服务体系。前端工程通过 Vite 构建，路由中包含首页、登录页、工作台、图库、相册详情和个性化设计页面；状态管理使用 Pinia，网络请求通过 Axios 封装；图像处理部分由 Canvas 与 Web Workers 承担；本地图片和编辑数据通过 IndexedDB 持久化。后端工程由 common、gateway、auth-service、authz-service 等模块组成，common 提供实体、DTO、JWT 工具和 Redis 服务，gateway 作为统一入口，auth-service 负责登录和用户管理，authz-service 负责角色、权限、菜单管理。

在后端数据库设计方面，我重点采用 RBAC 模型。sys_user 保存用户基础信息、BCrypt 加密后的密码、状态、创建时间和最后登录时间；sys_role 保存角色名称、角色标识、描述和状态；sys_permission 保存权限名称、权限标识、资源类型、资源路径和请求方法；sys_menu 保存菜单层级、路由路径、组件路径、图标和排序；sys_user_role、sys_role_permission、sys_menu_permission 三张关联表分别维护用户与角色、角色与权限、菜单与权限之间的多对多关系。该结构清晰地将身份、角色、资源访问和前端菜单解耦，便于后期扩展。

在前端本地数据库设计方面，IndexedDB 更适合存储 Blob、DataURL 和较大的图片编辑数据。images 表不仅保存图片本身，还保存调色、裁切、滤镜、个性化图层等 JSON 字段；albums 表用于相册管理；history 表用于撤销重做历史持久化。为了提高可维护性，代码中还设计了 BaseRepository 抽象类，将日志、数据库操作和预留服务器同步流程统一起来，ImageRepository、AlbumRepository、HistoryRepository 分别负责图片、相册和历史记录。本周的设计工作使系统从“功能集合”进一步明确为“分层清晰、数据闭环”的完整应用。
