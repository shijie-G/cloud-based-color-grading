# 用户登录及权限系统 - 完整流程总结

## 一、用户登录完整流程

### 流程图

```
用户输入账号密码
    ↓
前端发送 POST /auth/login
    ↓
Gateway 检查白名单（/auth/login在白名单中）
    ↓
转发到 Auth Service (8081)
    ↓
AuthServiceImpl.login()
    ├─ 1. 检查账户是否锁定 (Redis)
    ├─ 2. 查询用户信息 (MySQL)
    ├─ 3. 检查用户状态 (status=0正常)
    ├─ 4. BCrypt验证密码
    ├─ 5. 清除登录失败记录 (Redis)
    ├─ 6. 生成JWT Token (HS512)
    ├─ 7. 存储Token到Redis (key: token:{userId})
    ├─ 8. 更新最后登录时间 (MySQL)
    ├─ 9. 记录审计日志
    └─ 10. 返回登录响应
    ↓
返回给前端: {token, userId, username, roles, permissions, menus}
    ↓
前端保存Token到localStorage
```

### 关键代码

```java
// 1. 密码验证
BCryptPasswordEncoder encoder = new BCryptPasswordEncoder();
boolean matches = encoder.matches(password, user.getPassword());

// 2. 生成Token
String token = jwtTokenProvider.generateToken(userId, username, roles);

// 3. 存储到Redis
redisService.saveToken(userId, token);
// Redis: SET token:1 {token} EX 7200
```

### 登录失败处理

```
登录失败
    ↓
Redis: INCR login:fail:{username}
    ↓
失败次数 >= 5次？
    ├─ 是 → 锁定账户15分钟
    │       Redis: SET account:locked:{username} 1 EX 900
    └─ 否 → 允许继续尝试
```

## 二、Token验证完整流程

### 流程图

```
前端发送请求 (携带Token)
    ↓
GET /users
Authorization: Bearer {token}
    ↓
Gateway JwtAuthenticationFilter
    ├─ 1. 检查白名单
    │   └─ /users 不在白名单，需要验证
    ├─ 2. 提取Token
    │   └─ 去掉 "Bearer " 前缀
    ├─ 3. 验证Token签名和有效期
    │   └─ JwtTokenProvider.validateToken()
    ├─ 4. 从Token提取用户信息
    │   ├─ userId = 1
    │   ├─ username = "admin"
    │   └─ roles = ["ROLE_ADMIN"]
    ├─ 5. Redis验证Token
    │   ├─ GET token:1
    │   └─ 比对Token是否一致
    ├─ 6. 检查是否需要刷新
    │   └─ 剩余时间 < 30分钟 → 生成新Token
    ├─ 7. 添加用户信息到请求头
    │   ├─ X-User-Id: 1
    │   ├─ X-User-Name: admin
    │   └─ X-User-Roles: ROLE_ADMIN
    └─ 8. 转发到后端服务
    ↓
Auth Service 处理业务逻辑
    ├─ 从请求头获取用户信息
    └─ 执行业务操作
    ↓
返回响应给前端
```

### 关键代码

```java
// 1. Token验证
if (!jwtTokenProvider.validateToken(token)) {
    return unauthorized(exchange.getResponse());
}

// 2. Redis验证
String storedToken = redisService.getToken(userId);
if (storedToken == null || !storedToken.equals(token)) {
    return unauthorized(exchange.getResponse());
}

// 3. 自动刷新
if (remainingValidity < refreshThreshold) {
    String newToken = jwtTokenProvider.generateToken(userId, username, roles);
    redisService.saveToken(userId, newToken);
    response.getHeaders().add("Authorization", "Bearer " + newToken);
}
```

## 三、RBAC权限模型

### 数据模型

```
用户 (User)
    ↓ N:M (sys_user_role)
角色 (Role)
    ↓ N:M (sys_role_permission)
权限 (Permission)
    ↓ N:M (sys_menu_permission)
菜单 (Menu)
```

### 权限查询SQL

```sql
-- 查询用户的所有权限
SELECT DISTINCT p.*
FROM sys_user u
JOIN sys_user_role ur ON u.id = ur.user_id
JOIN sys_role r ON ur.role_id = r.id
JOIN sys_role_permission rp ON r.id = rp.role_id
JOIN sys_permission p ON rp.permission_id = p.id
WHERE u.id = ? AND u.status = 0 AND r.status = 0;

-- 查询用户的所有菜单
SELECT DISTINCT m.*
FROM sys_user u
JOIN sys_user_role ur ON u.id = ur.user_id
JOIN sys_role r ON ur.role_id = r.id
JOIN sys_role_permission rp ON r.id = rp.role_id
JOIN sys_menu_permission mp ON rp.permission_id = mp.permission_id
JOIN sys_menu m ON mp.menu_id = m.id
WHERE u.id = ? AND u.status = 0 AND r.status = 0 
  AND m.status = 0 AND m.visible = 0
ORDER BY m.sort_order;
```

### 权限检查流程

```
用户请求 API
    ↓
Gateway 验证Token
    ↓
转发到后端服务
    ↓
后端服务检查权限
    ├─ 从Redis获取用户权限
    │   └─ Key: permissions:{userId}
    ├─ 如果Redis没有，从数据库查询
    │   └─ 查询用户→角色→权限
    ├─ 检查是否有对应权限
    │   └─ 权限标识: system:user:query
    └─ 有权限 → 执行业务逻辑
       无权限 → 返回403
```

## 五、Redis缓存策略

### 缓存的数据

| Key格式 | Value | TTL | 说明 |
|---------|-------|-----|------|
| `token:{userId}` | JWT Token字符串 | 2小时 | 用户Token |
| `permissions:{userId}` | 权限列表JSON | 2小时 | 用户权限缓存 |
| `login:fail:{username}` | 失败次数 | 15分钟 | 登录失败计数 |
| `account:locked:{username}` | 1 | 15分钟 | 账户锁定标记 |

### 缓存更新策略

```
1. Token缓存
   - 登录时: SET token:{userId} {token} EX 7200
   - 刷新时: SET token:{userId} {newToken} EX 7200
   - 登出时: DEL token:{userId}

2. 权限缓存
   - 首次查询: 从数据库查询 → 存入Redis
   - 后续查询: 直接从Redis获取
   - 权限变更: DEL permissions:{userId}
   - 登出时: DEL permissions:{userId}

3. 登录失败
   - 失败时: INCR login:fail:{username}
   - 成功时: DEL login:fail:{username}
   - 自动过期: 15分钟

4. 账户锁定
   - 锁定时: SET account:locked:{username} 1 EX 900
   - 解锁时: DEL account:locked:{username}
   - 自动过期: 15分钟
```

## 七、常见问题

### Q1: 为什么需要Redis验证Token？
A: JWT本身无法主动失效，Redis验证可以实现：
- 用户登出后立即失效
- 强制用户重新登录
- 防止Token被盗用

### Q2: Token刷新机制如何工作？
A: 
- Token有效期2小时
- 剩余时间<30分钟时自动刷新
- 新Token在响应头返回
- 前端无感知更新

### Q3: 如何实现单点登录（SSO）？
A: 当前实现支持多端登录，如需单点登录：
- 登录时删除旧Token
- 只保留最新Token
- 旧Token验证失败

### Q4: 权限如何缓存？
A: 
- 首次查询从数据库加载
- 存入Redis（2小时）
- 权限变更时清除缓存
- 下次查询重新加载

### Q5: 如何强制用户下线？
A: 
```java
// 删除Redis中的Token
redisService.deleteToken(userId);
// 用户下次请求时验证失败
```
