# 后端接口完整文档

## 系统架构概览

本系统采用微服务架构，包含以下服务：

- **Gateway (网关服务)**: 端口 8080 - 统一入口，负责路由转发、JWT验证和权限校验
- **Auth Service (认证服务)**: 端口 8081 - 负责用户认证、用户管理
- **Authz Service (授权服务)**: 端口 8082 - 负责角色、权限、菜单管理

## 统一响应格式

所有接口（除特殊说明外）均返回以下格式：

```json
{
  "code": 200,
  "message": "操作成功",
  "data": {}
}
```

## 错误码说明

| 错误码 | 说明 |
|--------|------|
| 200 | 操作成功 |
| 400 | 请求参数错误 |
| 401 | 未授权（令牌无效或过期） |
| 403 | 禁止访问（账户被禁用或无权限） |
| 404 | 资源不存在 |
| 409 | 资源冲突（如用户名已存在） |
| 500 | 服务器内部错误 |

# 一、Auth Service (认证服务) - 端口 8081

## 1. 认证接口 (AuthController)

基础路径: `/auth`

### 1.1 用户登录

- **接口**: `POST /auth/login`
- **网关访问**: `POST http://localhost:8080/auth/login`
- **功能**: 用户登录认证，返回JWT令牌和用户信息
- **是否需要认证**: 否（白名单）

**请求参数**:
```json
{
  "username": "admin",      // 必填，用户名
  "password": "admin123"    // 必填，密码
}
```

**成功响应** (200):
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzUxMiJ9...",
    "userId": 1,
    "username": "admin",
    "nickname": "管理员",
    "roles": ["ROLE_ADMIN"],
    "permissions": ["user:create", "user:read"],
    "menus": [
      {
        "id": 1,
        "parentId": 0,
        "menuName": "系统管理",
        "menuPath": "/system",
        "component": "Layout",
        "icon": "setting",
        "sortOrder": 1,
        "children": []
      }
    ]
  }
}
```

**错误响应**:
- `401`: 用户名或密码错误
- `403`: 账户被锁定或禁用
- `500`: 登录失败


---

### 1.2 用户登出

- **接口**: `POST /auth/logout`
- **网关访问**: `POST http://localhost:8080/auth/logout`
- **功能**: 用户登出，清除令牌和缓存
- **是否需要认证**: 是

**请求头**:
```
Authorization: Bearer {token}
X-User-Id: 1
```

**成功响应** (200):
```json
{
  "code": 200,
  "message": "操作成功",
  "data": null
}
```

**错误响应**:
- `500`: 登出失败

---

### 1.3 刷新令牌

- **接口**: `POST /auth/refresh`
- **网关访问**: `POST http://localhost:8080/auth/refresh`
- **功能**: 刷新JWT令牌，延长有效期
- **是否需要认证**: 是

**请求头**:
```
Authorization: Bearer {token}
```

**成功响应** (200):
```json
{
  "code": 200,
  "message": "操作成功",
  "data": "eyJhbGciOiJIUzUxMiJ9..."  // 新令牌
}
```

**错误响应**:
- `401`: 令牌格式错误或令牌无效
- `500`: 刷新令牌失败

## 2. 用户管理接口 (UserController)

基础路径: `/users`

### 2.1 创建用户

- **接口**: `POST /users`
- **网关访问**: `POST http://localhost:8080/users`
- **功能**: 创建新用户，密码自动加密
- **是否需要认证**: 是
- **所需权限**: user:create

**请求参数**:
```json
{
  "username": "zhangsan",           // 必填，用户名（唯一）
  "password": "123456",             // 必填，密码
  "nickname": "张三",               // 可选，昵称
  "email": "zhangsan@example.com",  // 可选，邮箱
  "phone": "13800138000"            // 可选，手机号
```

**成功响应** (200):
```json
{
  "code": 200,
  "message": "操作成功",
  "data": {
    "id": 2,
    "username": "zhangsan",
    "nickname": "张三",
    "email": "zhangsan@example.com",
    "phone": "13800138000",
    "status": 0,
    "createTime": "2026-03-14T10:00:00"
```

**错误响应**:

# 五、认证与授权机制

## 1. JWT令牌认证

除登录接口外，所有接口都需要在请求头中携带JWT令牌：

```
Authorization: Bearer {token}
```

**令牌配置**:
- 密钥: 可通过环境变量 `JWT_SECRET` 配置
- 有效期: 2小时（7200000毫秒），可通过 `JWT_EXPIRATION` 配置
- 刷新阈值: 30分钟（1800000毫秒），可通过 `JWT_REFRESH_THRESHOLD` 配置

## 2. 网关白名单

以下路径无需认证即可访问：
- `/auth/login` - 登录接口
- `/auth/register` - 注册接口（如果实现）
- `/actuator/**` - 健康检查接口
- `/favicon.ico` - 图标

## 3. 权限校验流程

1. 用户请求到达网关
2. 网关验证JWT令牌有效性
3. 网关提取用户ID，调用 authz-service 的 `/api/permissions/check` 接口
4. authz-service 检查用户是否有权限访问该资源
5. 如果有权限，网关转发请求到后端服务；否则返回403错误

## 4. 请求头传递

网关验证通过后，会在转发的请求头中添加以下信息：
- `X-User-Id`: 用户ID
- `X-Username`: 用户名
- `X-Roles`: 用户角色（逗号分隔）

后端服务可以直接从请求头获取这些信息，无需再次验证。

# 六、安全特性

## 1. 密码安全

- **加密算法**: BCrypt
- **密码存储**: 所有密码均经过BCrypt加密后存储
- **密码传输**: 建议使用HTTPS传输

## 2. 登录失败锁定

- **最大失败次数**: 5次（可通过 `LOGIN_MAX_FAILURES` 配置）
- **锁定时长**: 15分钟（900秒，可通过 `LOGIN_LOCK_DURATION` 配置）
- **锁定机制**: 连续登录失败达到最大次数后，账户将被临时锁定

## 3. 令牌管理

- **令牌存储**: Redis
- **令牌失效场景**:
  - 用户主动登出
  - 用户密码被修改
  - 用户密码被重置
  - 用户账户被禁用
  - 令牌过期

## 4. 权限缓存

- **缓存存储**: Redis
- **缓存时长**: 30分钟（1800秒，可通过 `PERMISSION_CACHE_TTL` 配置）
- **缓存清除场景**:
  - 用户角色变更
  - 角色权限变更
  - 用户被禁用

## 5. 安全审计

- **审计日志**: 可通过 `SECURITY_AUDIT_ENABLED` 启用/禁用
- **审计内容**: 登录、登出、权限检查等关键操作
